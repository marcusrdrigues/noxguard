# noxguard 0.5: citations by id

Status: scope approved by Marcus (2026-10-10, decision 1 of the Havr.IA guardrails spec); not implemented. Additive: numbered citations (`[1]`) stay the default and keep working unchanged.

## Why

`CitationGuard` (0.3) checks answers whose sources are numbered `[1]` to `[99]`. Many RAG apps cite by **id** instead: a legal assistant cites `[cdc-art-6]` or `[sumula-stj-297]`, because the id tells the reader where the passage comes from, and because the app's own retrieval, logs and evaluation already use those ids. Today such an app has two bad options:

1. Number the passages for the model and translate back. The model loses the id, and every app repeats the translation.
2. Skip the guard.

noxeval 0.6 adds the same feature on the evaluation side (`mustCite`, `citation-unknown`). This spec is the production side: noxeval proves it before the release, noxguard enforces it on every answer.

## API

```java
List<Source> sources = List.of(
    Source.of("cdc-art-49", text49),
    Source.of("sumula-stj-297", text297));

CitationGuard guard = CitationGuard.builder()
    .allowNames(List.of("CDC", "STJ"))
    .citationPattern(CitationGuard.ID_PATTERN)   // optional; the default for Source lists
    .build();

CitationResult result = guard.check(answer, sources, question);
result.text();        // corrected citations are written back as [id]
result.citedIds();    // ids cited by the final text, in order of first appearance
```

- `Source(String id, String text)`: a record. `id` matches `[A-Za-z0-9][A-Za-z0-9._:/-]{0,99}` and is unique in the list (duplicate or malformed id: `IllegalArgumentException`).
- `CitationGuard.ID_PATTERN` is `\[([A-Za-z0-9][\w.:/-]*)\]`, the same default as noxeval 0.6, so one pattern serves both projects. `citationPattern(Pattern)` overrides it; the pattern must have exactly one capturing group.
- `CitationGuard.withIds(List<Source>)` builds the prompt side, like `numbered` does today: each passage as `[id] text`, so the ids the model sees and the ids the guard checks can't drift.
- `check(String, List<String>)` and `numbered(...)` stay exactly as in 0.3.

## Rules

Same as 0.3, with ids in place of numbers:

| Case | Outcome |
| --- | --- |
| Sentence cites a known id, and its details are in that source | `KEPT` |
| Details are in another received source | `RECITED`: the citation is rewritten to that source's id |
| A detail is in no received source | `REMOVED`, and a following sentence that leans on it goes too |
| Sentence cites an id **not in the list** | `REMOVED`, with the new reason `UNKNOWN_SOURCE`. This is an invented source, the worst failure a legal answer can have |
| `[3]` in id mode, with no source whose id is `3` | Same as an unknown id: in id mode a number is just an id |

## Result types

The records gain components, which changes their canonical constructors. They are results, not inputs, so app code should not be building them; the change is listed under "Changed" in the changelog.

- `CitationResult.citedIds()`: `List<String>`. In numbered mode it holds the numbers as text (`"1"`, `"2"`), so code that reads it works in both modes. `cites()` stays.
- `SentenceCheck.citedIds()`: the same, per sentence.
- `SentenceCheck.Outcome` is unchanged. The new reason goes in `Detail`/the removal reason, so a `switch` over `Outcome` still compiles.

## Starter and reactor

- `noxguard.citations.mode`: `numbered` (default) or `ids`.
- `ReactorGuard.guard(stream, sources, question)` accepts `Supplier<List<Source>>` in addition to `Supplier<List<String>>`.

## Out of scope

- Checking that the cited passage **supports** the sentence in meaning. That stays with an evaluator (noxeval's judge); the guard checks ids and details.
- Knowing what an id means (that `cdc-art-6` is article 6 of the Brazilian consumer code). That is domain knowledge, and stays in the app.

## Acceptance

1. `[x]` with sources `[a, b]` removes the sentence with `UNKNOWN_SOURCE`.
2. A sentence citing `[a]` whose number is only in `b` comes out citing `[b]` (`RECITED`).
3. `withIds(sources)` output, fed back as the model's quote, passes unchanged.
4. Every 0.3 test passes unchanged in numbered mode.
5. A duplicate or malformed id in the source list is rejected at the call, never silently renamed.
6. noxeval 0.6 and noxguard 0.5 agree on the 1,500 generated cases from 0.3, converted to ids: the same ids flagged as unknown.
7. No new runtime dependency.
