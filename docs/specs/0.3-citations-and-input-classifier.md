# noxguard 0.3: a citation guard for RAG answers and an input classifier port

Status: draft (2026-10-06), for Marcus to approve. Additive: no 0.1 or 0.2 signature changes.

## Why

**Citation guard.** A RAG prompt says "use only the passages and never invent numbers or names". That is probability. Nox, the chat this library comes from, now does it in code (October 2026): the passages are numbered, the model ends each sentence with the number of its source, and the server checks every sentence before the answer is final. It is the same idea as the rest of noxguard: the model can write anything, the code decides what reaches the user.

For a legal product this is the core risk: case law with an invented case number, court or date. A Java team building that needs the check as a library, next to its Spring app, not as a TypeScript port.

What Nox learned, which the guard ships with:

- **Two outcomes, not one.** A detail that is in **no** source the model received: the sentence is removed. A detail that is in a received source but **not the cited one**: the sentence stays and the citation is corrected. The first run removed 10 true sentences in 8 answers, all of them only miscited.
- **Sentences end at `.`, `!`, `?` and line breaks, not at `:`.** Splitting at colons dropped "works at Vibetex: runs the AI layer [1]".
- **Arithmetic is not invention.** "3 years later" with 2023 and 2026 in the sources passes when both years are in the answer; "3 projects" does not.
- **Coherence.** When the first sentence is removed, a second one that depends on it ("He", "That", "Ele", "Isso") goes too.
- **Empty means "not confirmed".** When no informative sentence is left, the app gets a flag and shows its own "I couldn't find that confirmed" text.

**Input classifier port** (promised in 0.1 for 0.2, moved to 0.3). Apps call a classifier (a hosted model, like Jev in Nox) to flag prompt injection before the model runs. When that classifier times out or errors, does the message pass or get blocked? Today each app decides by accident. noxguard makes it a required, explicit choice.

## Citation guard (package `grounding`, in `noxguard-core`)

```java
CitationGuard guard = CitationGuard.builder()
    .allowNames(List.of("Nox", "Marcus Rodrigues"))     // names the answer may always say
    .locale(Locale.ENGLISH)                              // number words and dependent openers ("He", "That")
    .build();

List<String> sources = List.of(passage1, passage2, toolResult1);   // [1], [2], [3]: the order the model saw
CitationResult result = guard.check(answer, sources, question);

result.text();          // the answer with unsupported sentences removed and citations corrected
result.sentences();     // per sentence: KEPT, RECITED (citation corrected) or REMOVED, with the reason
result.empty();         // true when nothing informative is left: show your "not confirmed" text
result.cites();         // the source numbers the final text cites, for links
```

- Details: numbers (with "mil", "thousand", "million", "k"; "10 mil", "10.000", "10,000" and "dez mil" are the same), acronyms and capitalized names, the same rules as noxeval 0.5's ungrounded-detail check. One extractor, ported once, tested against the same cases in both projects.
- A detail from the question passes only in a sentence that negates it (the premise bait: "I didn't find a prize in 2024").
- Pure and immutable: no I/O, no model, thread-safe; `check` runs in microseconds for a three-sentence answer.
- Prompt side: `CitationGuard.numbered(sources)` returns the passages as `[1] text` blocks, so the numbering the model sees and the one the guard checks can't drift.
- Streaming: the guard runs on the complete answer (citations are only checkable once the sentence ends). With `noxguard-reactor`, `ReactorGuard` gains an optional citation step that emits `Replace` with the checked text at the end, like the foreign-link check does today. The limit is the same and stated in the README: the user may see a sentence that is then removed; render as plain text until the stream ends.

## Input classifier port (package `input`, in `noxguard-core`)

```java
InputClassifier jev = text -> /* call the hosted classifier */ Verdict.flagged(0.97, "injection");

GuardedClassifier guarded = GuardedClassifier.of(jev)
    .timeout(Duration.ofMillis(800))
    .onFailure(FailureMode.FAIL_OPEN)    // required: no default
    .build();

ClassifierOutcome outcome = guarded.classify(InputViews.of(message));   // the original and its decoded views
switch (outcome) {
    case ClassifierOutcome.Allowed a  -> ...;
    case ClassifierOutcome.Blocked b  -> reply(refusal);
    case ClassifierOutcome.Unavailable u -> ...;   // only with FAIL_OPEN: passed, but logged and counted
}
```

- `FailureMode` has no default: `build()` throws until the app chooses. Nox fails open (the output guards still run); a payments app may fail closed.
- The classifier sees every `InputViews` view (base64, ROT13, leetspeak decoded) and the highest score wins, as Nox does.
- `Unavailable` is its own case, so a dashboard can count how often the classifier was down instead of mixing it with "allowed".

## Spring Boot starter

- `noxguard.citations.allow-names` and `noxguard.citations.locale` create a `CitationGuard` bean (when set).
- A `GuardedClassifier` bean is created when the app defines an `InputClassifier` bean and sets `noxguard.input.on-failure` (`fail-open` or `fail-closed`) and `noxguard.input.timeout`. An `InputClassifier` bean without `on-failure` stops the app at startup, with the property named.

## Versions and dependencies

`0.3.0`. No new dependency in any module.

## Out of scope

- Checking meaning ("worked at" becoming "led"). That needs a model; Nox measures it in evaluation only, for cost.
- A Spring AI advisor. It keeps coming up and keeps being smaller than it looks: the guards already work on a `Flux<String>` from Spring AI. Revisit when someone asks for it.
- Languages beyond pt and en for number words and dependent openers.

## Tests

- The Nox cases ported: miscited sentence recited, invented detail removed, colon not splitting, year difference, "3 projects" removed, wrong arithmetic removed, coherence, empty answer, the premise bait.
- A differential run against Nox's TypeScript `checkCitations` on the site's real answers and passages (as 0.1 did for the stream guard).
- Classifier: timeout and exception under both failure modes, the build failing without a mode, the highest view winning.
- Starter: each bean and the startup failure.
